# tune — 모델별 프롬프트 튜너

입력: `$ARGUMENTS`

## 처리 절차

### 1. 모델 판별
`$ARGUMENTS`의 **첫 공백 이전 토큰**을 확인한다.

**(a) 첫 토큰이 아래 모델 키면** — 그 가이드를 쓴다(명시적 오버라이드). 나머지 전체가 프롬프트 초안이다.
- `opus`, `opus5`, `opus-5`     → `guides/opus-5.md`
- `opus4.8`, `opus4-8`, `4.8`   → `guides/opus-4-8.md`
- `fable`, `mythos`, `fable5`    → `guides/fable-5.md`
- `sonnet`, `sonnet5`           → `guides/sonnet-5.md`

**(b) 첫 토큰이 모델 키가 아니면** — **전체를 초안으로 간주**하고, 지금 이 세션이 실제로 실행 중인 모델(너 자신의 모델 정체성, 시스템 컨텍스트로 알 수 있다)을 위 가이드에 매핑한다:
- Opus 5 계열 → `guides/opus-5.md`
- Opus 4.8 계열 → `guides/opus-4-8.md`
- Fable 5 / Mythos 5 → `guides/fable-5.md`
- Sonnet 5 계열 → `guides/sonnet-5.md`
- 매핑에 없는 모델 → `guides/opus-5.md`를 쓰되 미지원 모델임을 함께 알린다.

자동 감지로 골랐을 때는 응답 맨 앞에 `※ 세션 모델 자동 감지: <모델명> → <가이드>` 한 줄을 남긴다.

> 주의: (a)로 명시 지정한 모델이 현재 세션 실행 모델과 다르면, 튜닝 전에
> `※ 주의: 세션은 <실제 모델> 실행 중 — <지정 모델> 튜닝본은 이 세션의 답변 성향과 어긋날 수 있음` 경고 한 줄을 먼저 출력한다.
> (다른 모델용 프롬프트를 준비하는 의도일 수 있으므로 경고만 하고 진행한다.)
> Fable 5는 안전 라우팅으로 Opus 4.8에 폴백될 수 있어, 감지/선택 모델과 실제 응답 모델이 다를 수 있음을 감안한다.

### 2. 가이드 로드
판별된 경로의 파일을 Read 도구로 읽는다. **그 파일만** 읽고, 다른 모델 가이드는 읽지 않는다.

### 3. 튜닝
로드한 가이드의 규칙에 따라 초안을 재작성한다.
- 원래 **의도는 절대 바꾸지 않는다.** 명확화·구조화·범위 명시만 한다.
- 초안에 없던 사실·제약을 지어내지 않는다.
- effort / thinking / temperature 같은 **설정 레이어 항목은 프롬프트 본문에 넣지 않는다.**
  권장이 있으면 튜닝본 아래 `※` 메모로만 남긴다.
- 정보가 부족한 지점이 있어도 **사용자에게 되묻지 않는다.** 초안 의도를 해치지 않는 가장 자연스러운 해석으로 튜닝하고, 대상·경로처럼 사용자만 아는 값은 튜닝본에 `<대상 프로젝트 경로>` 같은 플레이스홀더로 표시한다. 어떤 해석을 택했는지는 튜닝본 아래 `※` 메모 한 줄로 남긴다.

### 4. 표시
`## 튜닝된 프롬프트` 아래에 재작성 결과를 먼저 보여준다. 설정 권장은 그 아래 `※` 메모.

### 5. 실행 전 설정 확인 (설정 권장이 있을 때만)
`※` 설정 권장(effort/thinking 등)을 남겼다면 **바로 실행하지 않고 여기서 턴을 마친다.** 메모 아래에 다음 안내를 붙인다:

> 권장 설정을 적용하려면 지금 `/model`(또는 클라이언트 설정)에서 조정한 뒤 **"계속"**이라고 답해주세요. 현재 설정 그대로 진행하려면 **"바로"**라고 답해주세요.

- 사용자가 진행 의사를 밝히면(계속/바로/그 밖의 진행 표현) 다음 턴에서 `## 답변`을 수행한다. 설정 변경 여부는 스킬이 확인할 수 없으므로 묻지 말고 그대로 진행한다.
- 사용자가 초안을 수정하거나 다른 요청을 하면 실행을 중단하고 그 요청을 따른다.

설정 권장이 없으면 이 단계를 건너뛴다.

### 6. 실행
`## 답변` 아래에 튜닝된 프롬프트를 그대로 수행한 결과를 낸다.
(5단계에서 멈췄던 경우, 실행 시점의 세션 설정이 곧 사용자가 선택한 설정이다.)
튜닝본에 플레이스홀더가 남아 있으면 멈추지 말고 **일반형으로 수행**한다(예: 대상 미지정 구현 요청 → 스택 무관 설계 + 대표 스택 참조 구현).
