# tune — 모델별 프롬프트 튜너

입력: `$ARGUMENTS`

## 처리 절차

### 1. 모델 판별 (첫 토큰)
`$ARGUMENTS`의 **첫 공백 이전 토큰**을 모델 키로 본다. 나머지 전체가 프롬프트 초안이다.
매핑:
- `opus`, `opus5`, `opus-5`     → `guides/opus-5.md`
- `opus4.8`, `opus4-8`, `4.8`   → `guides/opus-4-8.md`
- `fable`, `mythos`, `fable5`    → `guides/fable-5.md`
- `sonnet`, `sonnet5`           → `guides/sonnet-5.md`

첫 토큰이 위 어디에도 안 맞으면: **전체를 초안으로 간주**하고 기본 `guides/opus-5.md`를 쓰되,
응답 맨 앞에 `※ 모델 미지정 → Opus 5 가이드 기본 적용` 한 줄을 남긴다.

> 주의: 여기서 지정하는 모델은 **지금 이 세션이 실제로 실행 중인 모델**이어야 한다.
> (튜닝은 "이 프롬프트에 답할 모델"에 맞추는 것이므로, 세션 모델과 인자가 다르면 의미가 어긋난다.)
> Fable 5는 안전 라우팅으로 Opus 4.8에 폴백될 수 있어, 선택 모델과 실제 응답 모델이 다를 수 있음을 감안한다.

### 2. 가이드 로드
판별된 경로의 파일을 Read 도구로 읽는다. **그 파일만** 읽고, 다른 모델 가이드는 읽지 않는다.

### 3. 튜닝
로드한 가이드의 규칙에 따라 초안을 재작성한다.
- 원래 **의도는 절대 바꾸지 않는다.** 명확화·구조화·범위 명시만 한다.
- 초안에 없던 사실·제약을 지어내지 않는다.
- effort / thinking / temperature 같은 **설정 레이어 항목은 프롬프트 본문에 넣지 않는다.**
  권장이 있으면 튜닝본 아래 `※` 메모로만 남긴다.
- 정보 부족으로 튜닝이 애매한 핵심 지점이 있으면, 재작성 대신 **확인 질문 1개만** 하고 멈춘다.

### 4. 표시
`## 튜닝된 프롬프트` 아래에 재작성 결과를 먼저 보여준다. 설정 권장은 그 아래 `※` 메모.

### 5. 실행
이어서 `## 답변` 아래에 튜닝된 프롬프트를 그대로 수행한 결과를 낸다.
