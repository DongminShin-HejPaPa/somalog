# Fable 5 (Mythos 5) 튜닝 가이드

출처: platform.claude.com "Prompting Claude Fable 5". 아래는 튜닝 시 적용할 규칙.
Fable 5와 Mythos 5는 같은 계열이며, Fable 5는 생명과학·사이버·LLM R&D에 추가 안전장치가 있는 버전.

## 핵심 성향
이전 모델엔 너무 복잡·장시간·모호했던 end-to-end 작업(사람 기준 수 시간~수 주)을 겨냥한다.
쉬운 워크로드로만 시키면 역량을 과소평가하게 된다.

## 튜닝 규칙
1. **짧게 지시한다.** 지시 이행력이 강해 간결한 한 줄로도 잘 조종된다. 행동을 일일이 열거하지 않는다. (Opus용으로 촘촘히 쓴 프롬프트/스킬은 오히려 성능을 떨어뜨리니 걷어낸다.)
2. **과잉 정교화 억제.** 높은 effort에서 안 시킨 정리·리팩터·추상화를 덧붙이는 경향이 있어 "과잉설계 금지, 요청한 범위만" 같은 짧은 제약을 건다.
3. **진행 보고를 도구 결과에 근거.** 장시간 자율 실행 시 "진행 상황을 보고하기 전에 각 주장을 이 세션의 실제 도구 결과와 대조하라"를 넣으면 조작된 상태 보고가 거의 사라진다.
4. **"요청"만 말고 "이유"를 준다.** 왜 시키는지 맥락을 주면 의도를 스스로 추론해 관련 정보에 연결한다.
5. **병렬 서브에이전트를 전제로 설계.** 오케스트레이터↔서브에이전트 비동기 통신, 컨텍스트 유지하는 장수 서브에이전트를 활용. 자기검증은 self-critique보다 **신선한 컨텍스트의 검증 전용 서브에이전트**로.
6. **메모리 파일 활용.** 마크다운 파일 하나로 이전 실행의 교훈을 기록·참조하게 하면 성능이 특히 좋다.
7. **경계를 명시.** 요청하지 않은 행동(파괴적/비가역/공유 시스템 영향)은 하기 전에 확인하도록 지정.

## 하지 말 것
- **"네 추론을 응답에 재현/설명하라"류 지시 금지.** `reasoning_extraction` 거부 카테고리를 건드려 Opus 4.8 폴백이 늘어난다. 추론 가시성이 필요하면 구조화된 thinking 블록을 읽는 방식으로.

## 설정·라우팅 (프롬프트 본문 아님 → ※ 메모로만)
- effort가 1차 제어. 기본 high, 최난도 xhigh, 낮은 effort도 강력.
- thinking은 **항상 on**(adaptive 전용). `budget_tokens` 설정 시 400 에러.
- 공격적 사이버보안·생명과학·요약 사고 추출을 겨냥한 분류기에 걸리면 Opus 4.8로 폴백됨. 선의의 작업도 걸릴 수 있음.
